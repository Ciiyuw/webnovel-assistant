# 书项目档案与版本

## 四类资料与知情边界

| 类别 | 常见内容 | 更新依据 |
|---|---|---|
| 确定设定 | 世界规则、背景事实、人物初始卡、文风约定 | 作者已确定的决定 |
| 计划 | 全书方向、卷纲、故事段、近章计划、预计回收 | 作者采纳的规划，允许修订 |
| 已发生事实 | 定稿事件、当前状态、实际揭示、开放问题与兑现 | 作者接受的最终正文及出处 |
| 候选 | 脑洞、参考机制、双方草稿、未采用建议、备选终局 | 仅用于探索，不自动转正 |

确定的作者层真相、读者已经看到的信息、各人物实际掌握的信息分别记录。人物猜测、机构假说和不可靠叙述标明认知主体，不能等同于世界事实。计划中的事件尚未发生，不进入当前状态。

## 目录与最小建档

优先遵守已有目录和本书约定。普通文档项目可按职能使用 `创作管理/`、`设定集/`、`大纲/`、`正文/`，故事档案放 `创作管理/故事档案/`。作者希望分卷组织时也可采用：

```text
本书/
├── 创作管理/                 定位、协作约定、当前进度、讨论取舍
├── 设定集/                   世界规则、人物稳定设定、文风样本
├── 全书档案/                 当前状态、时间线、跨卷伏笔与承诺
└── 分卷/
    └── 第一卷/
        ├── 卷纲.md
        ├── 故事段/           本卷事件单元的计划与复盘
        ├── 章计划/
        ├── 候选稿/
        ├── 正文/
        └── 卷末交接.md
```

此结构是可选示意，不一次性复制空目录，不迁移现有正文只为符合模板。同一卷较短时故事段可以写在卷纲中；复杂到需要独立定位时再分文件或目录。全书章号保持唯一，故事段有稳定名称或编号，方便跨卷引用。

一本书一个根目录。书内不同故事段共享本书的全局档案；独立作品各自维护，只有通用写作方法和参考资料可以共享。不为新书自动复制旧作设定。仅讨论结构或工作流时不初始化故事档案；首次需要归档时按实际内容最小补齐。

模板由 AI 整理并裁剪，不要求作者填满，也不直接用作插件运行合同。

## 全局记忆与局部记忆

分目录解决定位，持续回写与按需读取解决承接。普通文档模式按规模逐步维护以下内容：

| 层级 | 内容 | 用途 |
|---|---|---|
| 当前进度与索引 | 当前采用版本、定稿到哪章、正在写哪段、下一步、资料路径 | 新会话的入口，保持简短 |
| 全书档案 | 核心人物当前状态、关系、能力与代价、时间、跨卷伏笔和读者承诺 | 跨卷延续变化，不逐卷重置 |
| 卷/故事段档案 | 本段发生了什么、关键选择、阶段兑现、局部开放问题 | 支持近期设计与复盘 |
| 定稿正文与逐章变化 | 实际事件及影响后续的变化，附章号和位置 | 核实依据，追溯摘要来源 |

每类记录有明确主文件；局部交接引用全局记录，不另维护一份相互竞争的“当前状态”。摘要是派生导航，正文与作者明确决定是核对依据。可给重要人物、伏笔或承诺编号，不强制每个细节都结构化。

人物当前状态考虑：位置、身体与能力、资源、当前目标、关系变化、已知/误信/未知信息。伏笔与承诺考虑：内容、埋设出处、已揭示程度、实际推进、预计回应阶段、状态和关联人物。预计回收留在计划字段，不写成实际回收。

章节档案记影响后续的变化，不重复摘录整章。未采用的 AI 新细节不进入状态；已定稿细节中可能形成期待的内容，标明待确认其后续用途，不自动扩成新的主线任务。

## 每章读取与跨会话

先读本书入口，定位当前卷、故事段和任务；随后读取本章计划、相关人物与规则、上章结尾原文、必要近章摘要、相关伏笔和文风样本。涉及旧事件时用索引或文本搜索取对应原文，不全量加载所有卷。

“最新摘要”不代表所有疑点已经核实。来源缺失、记录矛盾或版本过期时列出影响当前任务的缺口，不凭摘要补造前情。上下文多寡按任务调节，不设置能保证不遗忘的固定章数或字节数。

会话结束可更新简短交接：作品路径、当前版本和定稿章、上章结尾位置、近期计划、重要开放问题、待决定事项。它是导航，不代替故事事实档案；不要求作者重贴完整大纲或聊天历史。

## 普通文档模式的定稿归档

检查或写出草稿不等于定稿。依据作者接受版本、明确归档要求或已有自动定稿授权执行：

1. 确认最终稿路径与版本，保留已有稿件。已有 Git 项目按授权和项目约定备份；否则保存版本副本与变更说明，不为簿记擅自初始化仓库或提交无关文件。
2. 提取摘要、时间地点、人物状态与关系、资源能力及代价、谁知道了什么、实际埋设/推进/兑现的开放问题。
3. 每项附章号、原文位置或短引用。重要歧义集中交作者裁决，明确事实自动整理；候选与未发生计划留在原类别。
4. 更新主档案、相关局部记录和当前进度，核对它们对应同一最终版本。保存失败时说明实际完成部分，不冒报全部归档成功。
5. 报告归档与备份的真实状态及下一章起点。

作者尚未接受的版本可留草稿摘要，但标注版本与候选状态，不更新定稿当前状态。部分采用时依据最终拼合版本归档。

## 换卷与改稿

卷末整理交接：实际起止状态、重要选择与代价、关系变化、信息揭示、已兑现承诺、跨卷未闭合问题及出处、下一卷计划和候选。新卷先读交接与相关全书档案，再读所需旧章原文；卷末不把尚未发生的后续设想写成事实。

已定稿情节改变时保留旧版本，标明改动范围，重新提取受影响事实；检查人物知情、时间、资源、伏笔和后续章节。过期摘要、状态及评审结论标明失效或更新，不能沿用旧“通过”结果。纯错别字按实际影响处理，不无谓重做全书。

## 接入系统与作品复用

webnovel-writer 项目读 [其接入边界](webnovel-writer-integration.md)；Oh Story 项目读 [其接入边界](oh-story-integration.md)。由实际运行系统维护结构化事实与派生视图，不另建第二套当前状态，不手改数据库、提交记录或投影。

两套系统并存时先辨明实际在用的事实链；不得默认向两边提交。迁移属于单独工作，需要核对来源、版本和产物后再选择权威系统。待结转文档标明状态，不混入已提交事实。

作品正文与设定留在作品目录。通用方法留在 skill 或作者指定的知识资料；满意样本保留出处及适用条件。不要把本书事实、作者私有笔记全文或固定机器路径写入通用 skill，不自动写回外部知识库。
