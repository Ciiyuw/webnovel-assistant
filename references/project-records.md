# 书项目档案与版本

## 区分四类资料

| 类别 | 常见内容 | 更新依据 |
|---|---|---|
| 确定设定 | 世界规则、背景事实、人物初始卡、风格约定 | 作者已确定的决定 |
| 计划 | 总纲、卷纲、近期章计划、预计埋设与回收 | 作者采纳的规划 |
| 已发生事实 | 定稿事件、当前状态、实际揭示、开放问题与兑现 | 作者接受的最终正文及出处 |
| 候选 | 脑洞、参考材料、AI 试写、未采用建议 | 可探索，不自动转正 |

人物猜测、机构假说和不可靠叙述标明认知主体，不等同作者层真相。实际知识边界按经历、转述或阅读档案记录。

## 按已有目录工作

优先遵守本书约定。没有现成结构时按当前需求补少量文件，可采用：

- `创作管理/`：定位、协作约定、拆书、候选、作者稿、验收记录、发布与复盘。
- `设定集/`：世界规则、人物卡、风格契约。
- `大纲/`：全书方向、卷/剧情段和近期章节计划。
- `正文/`：作者接受的章节版本。
- `创作管理/故事档案/`：仅普通文档模式使用的摘要、角色当前状态、开放问题和时间记录。

不为新书自动复制其他作品设定。未明确目标书项目时不将信息写进已有书目录。

复制模板时删除无关字段，保留真实缺口。模板是资产而非运行合同，不应原样写入插件。

## 普通文档模式的定稿归档

作者说检查稿件时先做评审；作者接受版本或明确要求定稿归档时才提取到已发生事实档案。

1. 确认最终稿路径与版本，保存已有作者稿。已有 Git 项目可以记录实际版本；否则保留版本副本与变更说明。不为簿记擅自初始化或提交无关仓库。
2. 整理章节摘要、时间地点、人物状态与关系变化、资源能力变化、信息揭示、实际埋设/推进/兑现的开放问题。
3. 每项附章号和正文位置/短引用；不能判断的事实暂记待核对。只有影响后续创作的重要歧义需要作者裁决，明确事实自动整理。
4. 更新本书人可读档案，保留变化来源。计划里的尚未发生事件继续留在大纲。
5. 报告档案和备份的真实完成情况、下一章起点。

作者尚未定稿时允许保存临时摘要，但注明草稿版本，不更新当前故事事实。后来改动情节，要重新提取受影响记录并检查后续承接；错别字按实际影响处理。

## 插件项目的档案

发现 `.story-system/` 与 `.webnovel/` 时，先读 [插件接入边界](webnovel-writer-integration.md)。不再建立第二套运行状态真源，也不手改插件数据库和投影。

尚未具备作者稿提交入口时，整理“待结转”文档可以帮助作者工作，但不能把它报告为插件已接受事实，亦不能将其混入已提交章节的当前状态。

## 跨会话与作品复用

可整理一份简短交接：作品路径、当前定稿章、近期计划、最后一章结尾、重要开放问题、待作者决定事项。它是导航，事实仍回到本书源文件核对。

风格样本优先使用作者满意原文和出处。通用方法留在 skill/知识资料，作品事实留在作品目录。不要将每本书的正文或设定写进 skill；不要自动写回外部知识库。
