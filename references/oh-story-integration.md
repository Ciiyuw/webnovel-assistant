# Oh Story 接入边界

用于作者要求使用 Oh Story 命令或协作对象已有该系统工程的情况。上游为 [zenstory-ai/oh-story-claudecode](https://github.com/zenstory-ai/oh-story-claudecode)。本文依据 2026-10-10 阅读的上游主分支文档；执行时读取实际安装版本的 skill、相关 references 和脚本，不假设所有版本相同。

## 方法与实际运行分开

可以独立吸收扫榜拆文、事件与情绪联动、滚动规划、按章召回状态的方法，不依赖安装 Oh Story。本 skill 不包含其代码，也不自动安装、部署 hooks、注册命令或专用代理。

实际运行时按作者指定路径或宿主提供的安装清单查找。阅读仓库文件不代表当前工具支持其命令和 custom agents；能力缺失时按该版本允许的降级方式执行，明确区分普通文档协作与完整系统运行。

## 按任务接入

- `story-long-scan`：真实榜单取样、整理并比较；先确认目标平台、题材与数据日期。
- `story-long-analyze`：依据实际可读正文拆解节奏、情绪、人物与兑现，不凭书名生成拆文结果。
- `story-long-write`：按请求层级进行结构讨论、设定、大纲、细纲或指定正文；检查当前任务要求的 references 和前置资料，不因名称含 write 就默认写正文。
- `story-review`：只有实际运行相应流程才报告其检查结果；当前主流程自查不能冒充独立代理审查。
- `story-import`：作者要求接入已有稿件时核对导入范围，保护原文，推断资料保持待确认；导入不自动授权续写。

执行前核对当前 skill 的范围、文风裁决、代理部署与提交要求。其默认批次、篇幅和检查规则不搬进普通文档模式作为必需门槛。

## 事实链与定稿

所查版本由 `追踪/_tracking-state.json` 管理结构化追踪，`上下文.md`、人物状态、伏笔和时间线等由提交工具派生。实际写入走该版本规定的 `tracking_commit.py` / `storyctl.py` 流程，核对最终正文版本与提交结果；不手改派生文件，不伪造检查成功或追踪回写。

AI 写出的候选稿、作者接受版本、系统提交及外部发布是不同状态。需要作者先审阅的共创稿，在系统自动提交前设置明确交接；是否支持暂停、采用手改最终版本及随后提交，必须查实际流程，未验证不能声称已有自动接口。不得为了省事把候选稿提交成作者接受的事实。

已有追踪状态时不另建第二套“当前人物/伏笔”主档案。普通文档讨论记录可以保留，但引用运行系统的事实，不与它竞争。

## 与 webnovel-writer 并存

两套工具的方法可以借鉴，同一本书的运行状态只选择一套系统管理。发现两套结构时先辨明哪个在用、另一套是否旧副本；不默认双写。迁移需单独核实事实与版本，不把 Oh Story 的追踪 JSON 转写为 webnovel-writer 的提交产物，反之亦然。

用户只要求本 skill 的共创讨论时无需接入任一系统；缺少可选插件不阻断普通文档工作。
