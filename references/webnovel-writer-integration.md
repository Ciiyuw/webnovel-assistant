# webnovel-writer 接入边界

用于用户要求插件操作，或协作对象已经是该插件书项目的情况。本文依据 webnovel-writer v6.2.1 的文件和代码检查整理；执行前核对实际版本与 skill，版本变化时以当前文件和脚本为准。

## 查找而非假设可用

按用户指定位置、当前宿主提供的插件路径或已安装清单查找插件。不要假定用户名、操作系统、缓存版本或仓库目录。上游项目为 [webnovel-writer](https://github.com/lingfengQAQ/webnovel-writer)，本 skill 不包含其代码，也不自动安装它。

插件是可选集成，不是本 skill 的依赖。找不到时继续普通文档辅助；执行插件任务确有依赖缺失时明确说明。

原插件属于 Claude Code 环境。读取其中的文件不意味着当前环境已经注册其斜杠命令或专用 Agent。按当前实际工具判断能否执行，不能编造调用记录。

## 适合辅助作者的能力

- `webnovel-init`：整理故事核心、建档；实际执行前按其规则确认具体方案和目标目录。
- `webnovel-plan`：在作者确定的总纲内补卷节拍、时间与章目标，不替作者重做全局方向。
- `webnovel-review`：实际 reviewer 检查设定、时间、连贯、人物和逻辑；文笔、情绪兑现与阅读吸引力由本 skill 另提建议，作者判断。
- `webnovel-query`：只读查状态与开放问题。
- `webnovel-learn`：按作者认可写法沉淀经验，不代替章节事实入账。
- `webnovel-doctor`：只读诊断，不能据此声称已修复或已安装依赖。

原 `webnovel-write` 默认包含 AI 起草整章。`--fast`、`--minimal` 仍包含起草步骤，只降低检查或润色强度；不能把这些选项作为作者稿保护或只审查入口。

## 事实归属

v6.2.1 写前约束来自 `.story-system/` 合同。写后 accepted CHAPTER_COMMIT 驱动状态、索引、摘要、记忆、向量等投影；`.webnovel/state.json` 等并非可手写的故事事实真源。

Data Agent 提取提交产物，runtime 负责写入；审查产物必须来自所要求的真实审查。不能由主流程伪造专用代理的结果、直接手改状态数据库或把“没有报错”当成事实链完成。

不要混用仓库中的 v7 Story Repo 草案与当前 v6 结构。

## 作者稿入口尚待实现

本 skill 没有作者稿自动导入/提交脚本。`webnovel-review` 的完成也不意味着完整事实入账。需要接入作者稿时，应另行实现并验证：

1. 传入指定书项目、章号、作者稿路径与版本并保护原稿。
2. 读取本章约束，做真实事实审查，作者决定修改。
3. 以最终版本提取事实，执行所需代理/产物流程与校验。
4. 调用提交与投影链，核实版本一致、提交接受、派生记录和备份。
5. 失败仅补跑相关步骤，保留作者正文，不自动重新起草。

v6.2.1 代码检查发现：提交服务仍按产物 `blocking_count` 拒绝入账。正文定点修复后，如果旧产物未经过有效修复验收，不能沿用它冒报通过；也不能为过关直接清零。接入实现须明确可追溯的修复处理方式。

## 状态报告

分别报告作者稿保留、检查、作者定稿、事实提取、提交、投影、备份。提交 rejected、校验 failed 或投影 failed 时不报告完整流程成功。

在未实现或未验证自动入口时，明确说“普通文档档案已更新”或“待插件结转资料已整理”，不声称已提交插件事实。外部发布另以作者明确授权和实际发布结果为准。
